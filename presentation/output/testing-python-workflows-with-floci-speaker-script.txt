Slide 44 | Alex Au | Post-talk bonus
Replay returns saved results instead of repeating work

A completed context.step is a saved result, not just a marker saying some code was visited. CreateOrder saves the returned order record. The wait helper also checkpoints that its approval-submission callback completed. After approval resumes execution, the handler is replayed from the beginning; the SDK returns that stored order and completed-submission result instead of making those external calls again. The later reserve, charge and confirm steps then run. This is checkpoint reuse of already completed steps. The SDK callback submitter still has at-least-once-per-retry semantics if interrupted before its checkpoint, and the test does not exercise replay after payment or every crash boundary.
